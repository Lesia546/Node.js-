# Перелік перевірок

Усі перевірки запускаються відтворюваними командами. `make <ціль>` — це тонка обгортка над `npm run <скрипт>`, щоб вигляд команд був однаковим для рев'ю.

## Каталог

| Перевірка                | Що ловить                                   | Команда (npm)                      | Ціль make          | Де запускається      | Статус     |
| ------------------------ | ------------------------------------------- | ---------------------------------- | ------------------ | -------------------- | ---------- |
| Формат                   | відхилення від Prettier                     | `npm run format:check`             | `make format`      | pre-commit, pre-push | працює     |
| Лінтер                   | типові помилки, заборонені імпорти          | `npm run lint`                     | `make lint`        | pre-commit, pre-push | працює     |
| Типи                     | помилки TypeScript                          | `npm run typecheck`                | `make typecheck`   | pre-commit, pre-push | працює     |
| Збірка                   | код, що не компілюється                     | `npm run build`                    | `make build`       | pre-push             | працює     |
| Тести (unit/smoke)       | регресії бізнес-логіки, запуск застосунку   | `npm test`                         | `make test`        | pre-push             | працює     |
| Smoke                    | `dist/app.js` стартує і завершується        | `npm run smoke`                    | `make smoke`       | pre-push             | працює     |
| Межі модулів             | цикли, заборонені залежності                | `npm run audit:deps`               | `make audit`       | pre-push             | планується |
| Невикористані залежності | зайві пакети в `package.json`               | `npx knip`                         | `make audit`       | вручну / аудит       | планується |
| Секрети                  | паролі й токени в репозиторії               | перевірка `.gitignore`, ревʼю diff | —                  | PR                   | вручну     |
| Інтеграційні тести       | запити до SQL Server, обмеження, транзакції | `npm run test:integration`         | `make integration` | PR                   | планується |
| E2E                      | ключові сценарії користувача                | `npm run test:e2e`                 | `make e2e`         | PR                   | планується |
| Mutation testing         | тести, що нічого не перевіряють             | окремий інструмент (ADR)           | `make mutation`    | вручну перед здачею  | планується |

Скрипти зі статусом «планується» додаються разом із відповідним кодом, а не наперед.

## Агрегатні цілі

| Ціль         | Склад                                       | Використання             |
| ------------ | ------------------------------------------- | ------------------------ |
| `make check` | format, lint, typecheck, build, test, smoke | pre-push, перед PR       |
| `make audit` | межі модулів і зайві залежності             | аудит «структура ↔ spec» |

## Git-хуки

| Хук          | Що запускає                         | Мета                            |
| ------------ | ----------------------------------- | ------------------------------- |
| `pre-commit` | `format:check`, `lint`, `typecheck` | швидко зупинити «брудний» коміт |
| `pre-push`   | `make check`                        | не відправити зламану збірку    |

Обхід (`--no-verify`) заборонений. Якщо хук заважає — виправляється хук або стандарт, а не пропускається перевірка.

## Докази роботи конвеєра

Зберігаються в `docs/evidence/` і згадуються в `DEFENSE.md`:

- `hook-blocks-dirty-commit.txt` — лог відхиленого коміту з порушенням форматування.
- `make-check.txt` — вивід успішного `make check` із версією (SHA) коміту.
- `audit.txt` — вивід `make audit` до і після виправлення порушень меж.

## Правила

1. Нова перевірка додається в цей каталог в тому самому PR, що й її скрипт.
2. Перевірка, що стала нестабільною (flaky), або виправляється, або видаляється з пояснювальним ADR. Її не вимикають мовчки.
3. Результат кожної обов'язкової перевірки відтворюється однією командою на чистому клоні: `npm ci && make check`.
